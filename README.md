# juutoki · 로컬 텍스트 수집

**[Windows ZIP 다운로드 · GitHub 로그인 불필요](https://github.com/akke-git/juutoki/releases/latest/download/juutoki-windows-x64.zip)**

Windows 실행 파일 배포는 [GitHub Actions 빌드 안내](docs/windows-build.md)를 참고하세요.
현재 DB의 일관된 스냅샷을 첫 실행용 데이터로 포함하며 기존 사용자 DB는 덮어쓰지 않습니다.

회차 목록 URL을 입력하여 작품 제목, 회차 번호·제목, 본문을 수집하는 테스트 웹입니다.
FastAPI + Playwright + SQLite로 실행합니다. 별도 DB 서버는 필요 없습니다.

## 실행

저장소에 소스 파일이 직접 들어 있으므로 clone 후 바로 설치할 수 있습니다.

```sh
git clone https://github.com/akke-git/juutoki.git
cd juutoki
```

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers" .venv/bin/python -m playwright install chromium
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

브라우저에서 http://127.0.0.1:8000 을 엽니다. Linux에서 브라우저 시스템 라이브러리가
없으면 Playwright의 공식 시스템 요구사항에 따라 `playwright install-deps chromium`이 필요할 수 있습니다.

소스로 실행할 때는 `data/`의 DB를 사용합니다. 포함된 1~299화 DB로 이어가려면
서버를 처음 시작하기 전에 다음을 실행하세요. 기존 DB가 있으면 덮어쓰지 않습니다.

```sh
.venv/bin/python -c 'from pathlib import Path; from runtime_paths import install_seed, data_dir; install_seed(Path("seed/newt.sqlite3"), data_dir() / "newt.sqlite3")'
```

## 테스트 방법

1. 회차 목록 URL을 입력하고 **목록 불러오기**를 누릅니다.
2. **범위 지정**에서 처음에는 1~2회차를 선택합니다.
3. **본문 미리보기**로 추출된 내용과 문단 순서를 확인합니다. 이 단계는 저장하지 않습니다.
4. **수집 시작**을 누릅니다. 성공한 각 회차는 즉시 DB에 저장됩니다.
5. 완료 또는 중지 시 성공·건너뜀 회차의 합본 TXT가 서버에 생성됩니다. **TXT 다운로드**로 받을 수 있습니다.
6. **저장된 작품**에서 DB의 본문을 다시 열거나 작품 전체를 TXT로 다운로드할 수 있습니다.

## 저장 위치

- DB: `data/newt.sqlite3`
- 작업별 TXT: `data/exports/<작업 ID>.txt` (UTF-8 BOM, 회차 오름차순)
- `NEWT_DATA_DIR` 환경변수로 저장 폴더를 변경할 수 있습니다.
- DB와 TXT는 실제 수집 결과입니다. 실패 회차를 임의 텍스트로 채우지 않습니다.
- 재수집은 원본 회차 URL을 기준으로 갱신합니다. 기본값은 기존 회차 건너뛰기입니다.
- 작업 기록과 본문은 재시작 후에도 유지됩니다. 실행 중이던 작업은 중단으로 표시하며,
  **미완료 재시도**로 남은 회차만 새 작업에서 수집합니다. 재시도 작업의 TXT에는 그 작업의 성공 회차만
  포함됩니다. 전체 합본은 **저장된 작품**에서 다운로드하세요.
- 수집 중지는 현재 회차 처리가 끝난 뒤 적용됩니다. 실패·중단된 회차는 재시도할 수 있습니다.
- 일시적인 본문 로딩 실패는 동일 브라우저 세션에서 한 번 다시 불러옵니다.
- 회차를 읽다가 오류가 발생하면 종류와 관계없이 현재 브라우저를 닫고 **60초 기다린 다음 새 세션에서
  같은 회차를 한 번 재시도**합니다. 이미 성공한 회차는 다시 요청하지 않습니다.
  다른 회차에서 오류가 발생하면 동일한 복구 절차를 적용합니다. 같은 회차가 새 세션에서도 실패하면 중지합니다.
  대기 시간·세션 재시작 횟수가 화면에 표시되며, 대기 중에도 **수집 중지**가 즉시 적용됩니다.
  대기 시작 시점까지의 TXT도 생성됩니다. 자동 복구 기록은 작업 정보의 `recovery_log`에 남습니다.
  서버 재시작 시 대기하던 작업은 중단으로 표시하며 임의로 재개하지 않습니다.
- 로그인·일일 조회 인증·접근 거부·HTTP 429·연결 오류 등도 새 세션에서 한 번 재시도합니다.
  이 동작이 인증을 완료하는 것은 아닙니다. 재시도 후에도 요구가 남아 있으면 자동으로 중지합니다.
  저장소 오류는 수집 오류와 구분하여 중지합니다.
  오류에는 페이지 응답 상태, 본문 요소 수 또는 사이트의 안내 메시지를 표시합니다.

## 다른 사이트

URL은 변경할 수 있습니다. 기본 CSS 선택자는 확인한 목록 구조를 대상으로 합니다.
다른 구조는 **고급 설정**에서 작품명, 회차 행, 링크, 번호, 페이지 이동, 본문 선택자를 조정합니다.
페이지 이동 링크는 같은 도메인·경로만 따라가며 최대 100개 목록 페이지를 읽습니다.
회차 번호는 목록의 번호를 사용하며 소제목 속 `(1)` 같은 숫자로 추정하지 않습니다.

목록은 HTTP로, 본문은 Chromium에서 사이트가 정상 표시한 텍스트를 읽습니다.
열린 Shadow DOM의 문단도 지원합니다. 암호화 API를 직접 호출·해독하거나 로그인·접근 제한을 우회하지 않습니다.
현재는 HTTP 응답에 회차 목록이 포함된 사이트를 지원합니다. 목록 자체가 JavaScript로만
표시되는 사이트, iframe 본문, 로그인 필수 사이트에는 별도 대응이 필요합니다.

## 서버 이전 범위

이 버전은 **로컬 검증용 프로토타입**입니다. 인증·사용자 격리 없이 공개 인터넷에 노출하지 마세요.
서버 이전 시 사용자 인증, 허용 사이트 목록, 작업 큐, 저장 공간·요청 수 제한, 백업을 추가해야 합니다.
현재 한 번에 한 수집 작업을 실행하며 작업 상태는 SQLite에 저장하고 실행 제어는 프로세스 메모리에서 합니다.
**Uvicorn 단일 worker**로 실행하세요. 여러 worker로 실행하려면 작업 큐와 잠금을 외부로 옮겨야 합니다.
URL의 기본 검증과 사설 IP 차단을 포함하지만 공개 서버에서는 네트워크 수준의 내부망 접근 차단도 필요합니다.
수집 권한이 있는 콘텐츠를 대상으로 사용하세요.
